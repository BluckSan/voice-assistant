# Голосовой ассистент RU/EN

Офлайн голосовой ассистент для Android, который понимает **русский и английский** и отвечает голосом на том языке, на котором к нему обратились. Это новая версия приложения «Голосовой ассистент» (`com.example.assistant`): логика переписана с нуля на Kotlin + Jetpack Compose, пакет `com.hakkiiler.voiceassistant`.

## Две сборки: full и lite

| | **full** | **lite** |
|---|---|---|
| Модели Vosk | внутри APK | скачиваются один раз при первом запуске |
| Размер APK (debug) | ~132 МБ (оценка) | ~18,5 МБ |
| Процессоры | arm64-v8a, armeabi-v7a, x86_64 | только arm64-v8a (почти все современные телефоны) |
| Интернет | только если скачать модель рисования | нужен только для загрузки моделей |
| Рисование | только arm64 | arm64 |

**lite** при первом запуске показывает экран (RU/EN): выбери «Русский + English», «Только русский» или «English only». Скачается только нужная модель:
- https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip (~46 МБ)
- https://alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip (~41 МБ)

Видно прогресс, есть кнопки «Отмена» и «Повторить». Архив распаковывается в `files/models/model-ru|model-en` внутри приложения, создаётся файл `uuid`, а сам архив удаляется. Второй язык можно докачать позже в Настройках. После загрузки приложение работает полностью офлайн.

## Как работает двуязычное распознавание

1. Звук с микрофона (16 кГц) один раз читается и подаётся **одновременно в две офлайн-модели Vosk**: `vosk-model-small-ru-0.22` и `vosk-model-small-en-us-0.15` (`data/stt/BilingualSpeechEngine.kt`).
2. Когда любая модель определила конец фразы, у второй забирается финальный результат, и получаются две гипотезы: RU и EN.
3. `domain/lang/LanguageSelector.kt` выбирает одну из них по оценке:
   `0.6 × средняя уверенность Vosk по словам + 0.4 × доля «знакомых» слов` (ключевые слова команд, числительные, названия приложений этого языка) + небольшой бонус языку предыдущей фразы. Модель «чужого» языка выдаёт абракадабру с низкой уверенностью и без ключевых слов, поэтому проигрывает.
4. Слово-активатор ищется в **обеих** гипотезах (английская модель часто слышит «ассистент» как "assistant"), с учётом падежей и мелких ошибок.
5. Ответ озвучивается системным Android TTS на выбранном языке. Пока ассистент говорит, микрофон не распознаётся, чтобы он не слышал сам себя.

В **Настройках** можно выбрать режим: **Авто RU+EN**, **только русский** или **только English**. С одним языком работает одна модель, и нагрузка на процессор вдвое меньше.

```
├── domain/            чистый Kotlin, покрыт unit-тестами
│   ├── model/         модели данных, VoiceCommand (намерения)
│   ├── parser/        CommandParser, Keywords (RU/EN), NumberWords, MathEvaluator, DateTimeParser, AppMatcher
│   ├── lang/          LanguageSelector, WakeWordDetector
│   ├── image/         ContentSafety (проверка запросов), PromptTranslator (RU→EN)
│   └── usecases/      ProcessVoiceCommandUseCase, Replies (ответы на 2 языках)
├── data/
│   ├── image/         рисование: DrawController, загрузка модели, JNI к stable-diffusion.cpp, сохранение/«поделиться»
│   ├── stt/           Vosk: загрузка моделей и двуязычный движок
│   ├── tts/           AssistantVoice (Android TextToSpeech)
│   ├── repository/    DataStore: настройки, события, команды, история чата
│   └── system/        SystemControlManager (громкость, фонарик, медиа…), ReminderManager
├── service/           AssistantService (foreground, микрофон), напоминания, BootReceiver
├── overlay/           плавающая кнопка поверх приложений
├── ui/                Compose: MainScreen + screens/ (Assistant, Events, Commands, Draw, Settings) + components/
└── di/                AppContainer (ручной DI)
app/src/main/cpp/      CMakeLists.txt, sdjni.cpp, vocab_clip_only.cpp, stable-diffusion.cpp/ (подмодуль)
app/src/main/resources/content_safety/blocked_terms.txt, prompt/ru_en.txt
```

Отличия от исходного APK:
- Firebase (вход через Google и Firestore) заменён на локальное хранилище DataStore, все данные на телефоне. Экрана профиля пока нет.
- Удалены неиспользуемые голосовые модели Piper/ONNX и дубли espeak-ng-data (~140 МБ).
- Вместо `QUERY_ALL_PACKAGES` используется `<queries>`. INTERNET нужен только для загрузки моделей: в lite — Vosk и модель рисования, в full — только модель рисования по кнопке.
- Огромный `MainContainer` разбит на отдельные экраны.

## Рисование (офлайн, на телефоне)

Вкладка **«Рисование»** генерирует картинки по текстовому описанию прямо на телефоне, без интернета и облачных фильтров.

- **Движок:** [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) (ggml, MIT), закреплён на коммите `2988060`, подключён git-подмодулем в `app/src/main/cpp/stable-diffusion.cpp`. Собирается через NDK/CMake в `libsdjni.so` (только arm64-v8a, CPU, `-O3`, `armv8.2-a+dotprod+i8mm+fp16`), JNI-обёртка: `app/src/main/cpp/sdjni.cpp`.
- **Почему CPU, а не NPU/GPU:** у Poco X7 Pro процессор MediaTek Dimensity 8400 с GPU Mali-G720. Готовые NPU-стеки для Stable Diffusion на Android в основном под Qualcomm, а Vulkan-бэкенд ggml на Mali пока нестабилен и требует отдельной сборки шейдеров. CPU-путь работает на любом arm64 с i8mm (ARMv8.6+, телефоны примерно с 2022 года); на старых процессорах экран честно пишет, что рисование не поддерживается, вместо падения.
- **Размер:** в .so попадает только словарь CLIP (`vocab_clip_only.cpp` вместо словарей T5/Gemma/Mistral/Qwen) — библиотека 8,6 МБ вместо 37 МБ. В lite-APK нативные библиотеки лежат сжатыми.

### Модель

| | |
|---|---|
| Модель | **SD-Turbo** (Stability AI), GGUF: UNet в q8_0, остальное f16 — `sd_turbo-f16-q8_0.gguf` |
| Ссылка | https://huggingface.co/Green-Sky/SD-Turbo-GGUF/resolve/19a31586d02d64a73b4419bc193b3ecfaf38e1f0/sd_turbo-f16-q8_0.gguf |
| Размер | 2 023 745 376 байт (~2,0 ГБ), SHA-256 `d50be765…ae51580` |
| Лицензия | [Stability AI Community License](https://huggingface.co/stabilityai/sd-turbo/blob/main/LICENSE.md): бесплатно для личного/некоммерческого использования и для бизнеса с выручкой до $1 млн в год (с регистрацией у Stability AI). Powered by Stability AI. |
| Быстрый декодер | **TAESD** (madebyollin, MIT), 9,8 МБ: https://huggingface.co/madebyollin/taesd/resolve/614f76814bbe30edbe2e627ace1c2234c81a2c0e/diffusion_pytorch_model.safetensors |

Почему SD-Turbo: она рисует 512×512 за 1–4 шага без CFG (одна прогонка UNet на шаг), а обычной SD 1.5 нужно ~20 шагов × 2 прогонки. На телефоне это разница между «около минуты» и «десять минут».

Модель **не входит в APK**: кнопка «Скачать» на экране рисования один раз качает её с Hugging Face в `files/image-models/` (нужно ~2,4 ГБ свободного места, лучше по Wi-Fi). Загрузка показывает прогресс, её можно поставить на паузу и продолжить с того же места (HTTP Range), при обрывах сети до 4 автоматических повторов, в конце проверяется SHA-256. Кнопка «Удалить модель» освобождает место.

### Экран и голос

- Поля: запрос, негативный запрос, шаги (1–8, по умолчанию 4), размер 256/384/512, CFG (1–4, по умолчанию 1 — так задумано для SD-Turbo; негативный запрос работает только при CFG > 1, и тогда каждый шаг вдвое дольше), seed (пусто — случайный), переключатель быстрого декодера TAESD.
- Прогресс по шагам, кнопка «Отмена», результат, **«В галерею»** (MediaStore → `Pictures/VoiceAssistant`) и **«Поделиться»**.
- Голосом: «нарисуй …» / "draw …" открывает вкладку и сразу запускает генерацию (`CommandParser.parseDraw`, тесты в `DrawCommandTest`). Если модели ещё нет — запрос подставится в поле, а ассистент попросит её скачать.
- **Русские запросы.** Текстовый энкодер SD-Turbo понимает только английский, поэтому сказанное по-русски переводится грубым пословным словарём (`app/src/main/resources/prompt/ru_en.txt`, ~330 слов и основ): «кота в космосе» → "cat in space". Результат видно в поле запроса, его можно поправить. Для лучших картинок пиши запрос по-английски.
- Генерация идёт в отдельном потоке (`DrawController`, корутина в области приложения), экран не гаснет, пока рисуется. Перед загрузкой модели проверяется свободная память (нужно ~2–2,5 ГБ); модель держится в памяти 3 минуты для следующей картинки и выгружается раньше, если система просит память (`onTrimMemory`).

### Проверка запросов

`domain/image/ContentSafety.kt` отклоняет **только** запросы на незаконный контент — сексуализированные изображения несовершеннолетних (CSAM): термин из `[always]`, или одновременно упоминание несовершеннолетнего (слова или возраст < 18) и сексуального контекста. Список терминов лежит отдельно в `app/src/main/resources/content_safety/blocked_terms.txt`. Других фильтров нет. Тесты: `ContentSafetyTest`.

### Сколько времени

На тестовом x86-сервере (6 потоков) 512×512 за 4 шага с TAESD рисуется ~21 с, 256×256 — ~5 с. Для Dimensity 8400 (4 потока на больших ядрах) ориентировочно, **не измерено на реальном телефоне**:

| Размер, 4 шага, TAESD | Оценка на Poco X7 Pro |
|---|---|
| 256×256 | ~10–25 с |
| 384×384 | ~25–50 с |
| 512×512 | ~45–90 с |

Плюс 5–15 с на первую загрузку модели в память. При долгой работе телефон греется и замедляется.

### Сборка нативной части

Нужны **NDK 27.0.12077973** и **CMake 3.22.1** (Android Studio → SDK Manager → SDK Tools, или `sdkmanager "ndk;27.0.12077973" "cmake;3.22.1"`). Исходники stable-diffusion.cpp — подмодуль:

```bash
git submodule update --init --recursive   # в git-клоне
bash scripts/fetch_sdcpp.sh               # если папки нет (скрипт сам проверит)
```

В zip-архиве с исходниками stable-diffusion.cpp уже лежит в урезанном виде (без примеров, документации, тестовых картинок и ненужных словарей), так что проект из архива собирается без интернета для исходников.

Первая сборка нативной части занимает несколько минут. Даже в debug-APK она собирается с `-O3`, иначе генерация в десятки раз медленнее.

## Как открыть в Android Studio

1. Установи Android Studio (Ladybug 2024.2 или новее) с JDK 17+, а в SDK Manager — NDK 27.0.12077973 и CMake 3.22.1.
   Скачай исходники stable-diffusion.cpp: `git submodule update --init --recursive` (или `bash scripts/fetch_sdcpp.sh`, если проект скачан архивом).
2. Только для сборки **full**: скачай модели (они большие, поэтому не лежат в архиве с исходниками). Сборке lite они не нужны.
   ```bash
   bash scripts/download_models.sh
   ```
   Они попадут в `app/src/full/assets/model-ru` и `model-en` (~156 МБ). На Windows скрипт можно запустить в Git Bash или WSL, либо вручную скачать архивы с https://alphacephei.com/vosk/models, распаковать в эти папки и положить в каждую файл `uuid` с любым текстом.
3. File → Open → выбери папку проекта и дождись синхронизации Gradle.
4. В панели Build Variants выбери `liteDebug` или `fullDebug`.
5. Подключи телефон с включённой отладкой по USB и нажми Run ▶.

## Как собрать из командной строки

```bash
./gradlew assembleLiteDebug                # app/build/outputs/apk/lite/debug/app-lite-debug.apk (~18,5 МБ)

bash scripts/download_models.sh            # один раз, только для full
./gradlew assembleFullDebug                # app/build/outputs/apk/full/debug/app-full-debug.apk (~123 МБ)

./gradlew testLiteDebugUnitTest            # 35 unit-тестов: парсер, выбор языка, «нарисуй», проверка запросов

```

Нужен Android SDK (platform 35, build-tools 35.0.0, NDK 27.0.12077973, CMake 3.22.1). Путь к нему укажи в `local.properties` (`sdk.dir=...`) или в переменной `ANDROID_HOME`.

## Первый запуск на телефоне

- Разреши **микрофон** и **уведомления**.
- **lite**: при первом запуске выбери язык и дождись загрузки моделей (лучше по Wi-Fi). Нужно ~250 МБ свободного места на время распаковки.
- **full**: при первом запуске модели копируются из APK в память телефона, это занимает 10–30 секунд.
- Проверь, что в системе есть голоса TTS для русского и английского (Настройки → «Системные настройки синтеза речи»; обычно это Google TTS).
- Чтобы ассистент открывал приложения, когда он в фоне, включи **«Плавающая кнопка»**: это даёт разрешение «поверх других окон», без которого Android 10+ не даёт запускать приложения из фона.
- Для точных напоминаний на Android 12+ разреши «Будильники и напоминания».

## Известные ограничения первой версии

- Small-модели Vosk компактные, но ошибаются чаще больших (WER ~ 10–20 %), особенно в шуме и на редких словах и названиях. Слово-активатор лучше выбирать из обычных слов словаря.
- В режиме «Авто» распознавание идёт двумя моделями, это примерно вдвое больше нагрузки на процессор и батарею при фоновом прослушивании.
- Смешанные фразы («открой Spotify») распознаются хуже, чем фразы на одном языке: имя на другом языке может исказиться.
- Даты вроде «пятнадцатого ноября» (порядковые числительные) пока не понимаются; работают «сегодня / завтра / послезавтра / день недели / через N минут / в 17:30 / в пять вечера».
- «Очистить память» на Android 8+ закрывает только фоновые процессы, полностью закрыть чужие приложения система не даёт.
- Меню питания без root открывается не на всех прошивках.
- Рисование: проверено сборкой, unit-тестами и прогоном той же JNI-обёртки с моделью на x86, но **ещё не запускалось на реальном телефоне**; время генерации в таблице — оценка. Нужен arm64 с i8mm (ARMv8.6+). Генерация не в foreground-сервисе: если свернуть приложение надолго, система может его выгрузить. Если запустить «нарисуй» голосом из фона без разрешения «поверх других окон», Android может не дать открыть экран — картинка всё равно появится на вкладке «Рисование».
